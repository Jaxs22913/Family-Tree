## Standing rules — these govern everything, do not relax them

1. **Evidence rule.** Do NOT accept online family trees as fact. A relationship is
   upgraded to CONFIRMED only on a primary record: an obituary or funeral record,
   a census, a marriage record, a death record, or multiple independent sources
   that agree.
2. **Facebook rule.** Facebook groups may be read for *leads only*. Nothing goes on
   the tree unless confirmed by a source outside Facebook.
3. **Include the unflattering** — slavery, crimes, conflicts — alongside the rest.
4. **Occupations for every individual**, plus fun facts and trades.
5. **Documents are embedded and readable in place**, never linked out.
6. Record conflicts rather than smoothing them. Withdraw claims publicly when they
   turn out to be wrong, rather than deleting them quietly.
7. Ask questions using the clickable multiple-choice format.

## Technique notes for whoever picks this up

**The National Archives 1950 census has a IIIF endpoint.** This is the best document
pipeline found so far — precise crops at native resolution, straight from `curl`, no
browser needed.

```
# 1. find the sheet
https://1950census.archives.gov/api/search/?name=<surname>&state=GA&county=<county>&ed=<ed>
#    the result carries "image" and "iiifUrl"
# 2. dimensions
https://1950census.archives.gov/iiif/2/<urlencoded-image-path>/info.json
# 3. any crop, any scale:  /{x},{y},{w},{h}/{width},/0/default.jpg
```

Joe Edd's sheet: `1950census/43290879-Georgia/43290879-Georgia-001356/43290879-Georgia-001356-0015.jpg`
(4038 × 4878). The composite in `docs/census-giddens1950.jpg` is three bands —
header, names, occupations — stitched with a grey divider at 2000px wide.

**The browser `javascript_tool` was broken all session** — it returned `undefined` for
every call, including `1+1`. The workaround that worked well: drive the **FamilySearch
search UI by URL** and read results with `get_page_text`. Results come back compactly
and legibly.

```
https://www.familysearch.org/search/record/results?q.surname=X~&q.givenName=Y~
  &q.birthLikeDate.from=&q.birthLikeDate.to=&q.birthLikePlace=&q.residencePlace=
  &f.collectionId=<id>&count=<n>
```

- `q.surname.exact=on` is **broken** — silently returns 0 results. Never use it.
- `q.residencePlace` works at **county** level ("Berrien, Georgia"), not state level.
- Fuzzy `~` on a given name expands to variants — `Jo~` matches John and Jack, so use
  exact given names when hunting a specific person.
- Collection IDs: 1850=1401638 · 1860=1473181 · 1870=1438024 · 1880=1417683 ·
  1900=1325221 · 1910=1727033 · 1920=1488411 · 1930=1810731 · 1940=2000219 ·
  1950=4464515 · WWI Draft=1968530 · WWII Draft=1861144

**Ancestry is a FREE account** — record pages mask data as `xx xxx xxxx` and bounce to
the $24.99/month join page. Two exceptions that *are* viewable: the **Find a Grave
index** and the **1950 census**. The "suggested records" list at the bottom of any
record page is visible even when the records themselves are not — that list is what
revealed the 1950 census. Worth scanning on every Ancestry page.

**Deploy pipeline** (cloud container → Mac → GitHub):
1. Edit in the container at `/home/claude/genealogy/site`
2. `node --check` the JS, then run the cross-reference validator and the Playwright
   render harness (53 `ERR_FILE_NOT_FOUND` are pre-existing missing portrait JPEGs —
   expected, not a regression)
3. Stage to a **fresh unique** `/mnt/user-data/outputs/vN/` — reusing a filename
   serves a cached copy
4. `device_commit_files` with `force:true`, then verify md5 on the Mac.
   *Note: JPEGs get re-encoded in transit and the md5 will differ — check dimensions
   and the JPEG start/end markers instead. JS files must match byte-for-byte.*
5. Commit, push, then confirm the live deploy with `curl` after ~90 seconds

**Editing `assets/data.js`** — the file mixes literal `—` `–` `→` characters AND
literal `—` escape sequences; `docs.js` stores literal backslash-u escapes.
Always `print(repr(...))` around the target before writing a replacement, or splice
by index between two stable markers. Assert match counts in the patch script.

## STANDING RULE — search every spelling, always

**A negative result means nothing until the name has been searched under every spelling a clerk,
an enumerator, or a machine might have produced.** This project has now lost real time to it more
than once, and it has produced at least two false "not found" conclusions.

**Why it happens.** These names were written down by whoever was holding the pen — a census taker
walking a road, a county clerk copying a deed, a registrar who had never met the deceased. Then a
century later a machine read that handwriting. Both steps guess, and both guess wrong.

**Variants already proven in this tree — every one of these is a real record:**

| Real name | Found in records as |
|---|---|
| McKinnon | **Kinnon** · **Kinon** · **McKennan** · **Chs M. Kinnon** · **Charles W Kinnon** |
| Carver | **Corver** |
| Hughes | **Hughs** |
| Ricketson | **Rickerson** |
| Giddens | **Giddings** · **Gideon** |
| Merritt | **Merit** |
| Spivey | **Spivy** |
| Story | **Storey** |
| Spivey (index error) | **Sping** |
| Luridy | **Gurdy** |
| Harper (OCR) | **Hacker** |
| orphan (OCR) | **or plan** |

**The McKinnon case is the clearest.** Searching the Telfair County deed books for
*"Charles McKinnon"* returns almost nothing. Searching the same books for *"Charles Kinnon"*
returns **thirteen matches in a single volume**. Same man, same book, same page — different guess
at a name.

**How to generate the variants:**
- **Mc / Mac** dropped entirely, or read as **M.**, **W.**, **N.**
- **Phonetic endings**: -on / -an / -en / -in (Kinnon, Kinnan, Kennon)
- **Terminal s** added or lost (Hughes/Hughs, Cribb/Cribbs, Yawn/Yawns)
- **Vowel swaps** in unstressed syllables (Carver/Corver, Merritt/Merit)
- **OCR confusions**: rn→m, m→rn, ll→U, cl→d, long-s→f, h→b, k→h
- **Initials instead of names** (J. M. Kinnon, Chs M. Kinnon)

**Practical rule for this project:** run the search under the true spelling first, then under at
least the Mc-dropped form and the nearest phonetic form, before recording a negative. On
FamilySearch use the fuzzy operator (`surname~`) on indexed searches, and run literal variants by
hand on full-text search, which does **not** fuzzy-match.

**And do not trust a bare `(0)`.** A real zero on FamilySearch shows the words *"No Results
Found."* A bare `(0)` with no message is a page that has not finished rendering; re-read it.

## AUDIT — what the spelling problem did and did not hide

Run deliberately after the spelling rule was written, to find out how much earlier work it had
quietly voided. **The answer is less than feared, but not nothing, and the reason is worth
knowing: the two search systems used in this project behave differently.**

### System A — FamilySearch *indexed record* search (censuses, slave schedules, USCT, oath books)

**Fuzzy-matches by default.** Proven in this project's own results: typing *Carver* returned
**Corver** and **McCarver**; *Giddens* returned **Gideon** and **Giddings**; *Spivey* returned
**Spivy**; *McKinnon* returned **Kenan, Kennon, Kinnon**.

**One failure found.** *Merritt* returned **0** against the 1860 slave schedule — yet the Mary
Turner transcription of Coffee County shows **Frederach Merit holding eight people**. Whether the
fuzzy match failed to bridge Merritt→Merit or the page simply had not finished rendering, **it was
a false negative**, and it was caught only because a different source was used for the same
question.

**Verdict: the slave-schedule sweep stands**, because its authority was the transcription
spreadsheets, not the FamilySearch screen. Had the search been the only source, the Merritt
household would have been missed entirely.

### System B — FamilySearch *full-text* search (county deed, probate, court books)

**Does NOT fuzzy-match. Literal string only. Every negative from it is suspect until re-run.**

Re-checks performed:
- *"Leonard Hacker"* in Irwin County — the spelling the machine actually produced for the will —
  returns **one match, the will page already read**. The negative on an Irwin estate inventory
  **holds**.
- *"estate of Charles Kinnon"* — returns Harris County, Georgia and Hood County, Texas.
  **No Telfair record. Negative holds.**

**And a nuance that matters more than the rule itself: OCR quality varies by volume, so the right
variant depends on which book you are searching.** The Telfair **probate and guardianship** book
renders the name correctly as *McKinnon* — which is how the four "orphan of Charles McKinnon"
bonds were found at all. The Telfair **deed** books render the same man as *Charles W Kinnon*,
*Charles M. Kinnon*, *Chs M. Kinnon*. Searching the probate book for *Kinnon* would have found
nothing, and searching the deed books for *McKinnon* found almost nothing. **Neither spelling is
the "right" one. Run both, always.**

### System C — Georgia Archives CONTENTdm (death certificates, pension files)

**Keyword, not fuzzy.** Re-ran the Hall siblings across ten variants — *Jessee, Rosetta,
Roseanna, Lee, Enoch, Kisiah, Keziah, Talley, Tolley, Tally* — filtered to Clinch, Atkinson,
Coffee, Berrien, Lanier, Ware, Lowndes and Irwin. **All clean. The original negative holds:** none
of Jane Hall's other children died in the free 1919–1927 window in this region.

### System D — Georgia Historic Newspapers

Full-text, not fuzzy. Only lightly used so far. **Any future use needs the full variant list**, and
its page-level OCR endpoint sits behind bot protection — pull the text out of the search JSON
(`format=json` returns `ocr_eng` per item) rather than fetching `/ocr.txt`.

### The worse hazard, which is not spelling at all

**Place standardisation can be silently wrong.** Henry S. C. Harper's 1880 entry is standardised to
*District 5, Chatham, Georgia* while the original reads *District 5, ED 58, **Irwin**, GA*. A whole
enumeration district of Irwin County is filed under a county three hundred miles away. **No
spelling variant would ever have caught that**, and it voided every county-filtered 1880 search on
Irwin. Where a county filter matters, check *Event Place (Original)* against *Event Place* on at
least one record before trusting the set.

### Net

Nothing currently published on the site is wrong because of spelling. One real false negative
(Merritt) was caught by a second source. The method rules are now recorded; the cost of this audit
was an hour, and the cost of not doing it would have been believing four negatives that had never
actually been tested.
